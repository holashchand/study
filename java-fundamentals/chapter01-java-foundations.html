1. What is Java?

History

  • 1995: James Gosling and team at Sun Microsystems created Java
  • Philosophy: "Write Once, Run Anywhere" (WORA) — compile once, run on any platform
  • Design goals: Platform independence, simplicity, security, robustness, network-centric

Java Today

  • #1 enterprise language: Used in 90% of Fortune 500 companies
  • Android development: Official language for Android apps
  • Frameworks: Spring, Hibernate, Apache Kafka, Apache Spark
  • Scalability: Powers Netflix, Twitter, LinkedIn, Google services

Key Design Goals

  • Platform-independent: Bytecode runs on JVM, not CPU-specific
  • Object-oriented: Everything is an object (except primitives)
  • Secure: Type-safe, no direct memory access, runtime checks
  • Robust: Exception handling, garbage collection, automatic memory management
  • Simple: Familiar C/C++ syntax but simpler, no pointers

2. JRE vs JDK vs JVM

Architecture Diagram

┌─────────────────────────────────────────┐
│              JDK (Java Development Kit) │
│  ┌───────────────────────────────────┐  │
│  │     JRE (Java Runtime Environment)│  │
│  │  ┌─────────────────────────────┐  │  │
│  │  │  JVM (Java Virtual Machine) │  │  │
│  │  │   Executes .class bytecode  │  │  │
│  │  │   Platform-specific binary  │  │  │
│  │  └─────────────────────────────┘  │  │
│  │  + Java Class Libraries (stdlib)   │  │
│  │  + Runtime Environment             │  │
│  └───────────────────────────────────┘  │
│  + javac (compiler)                     │
│  + javadoc (documentation generator)    │
│  + jdb (debugger)                       │
│  + jshell (REPL)                        │
│  + Other development tools              │
└─────────────────────────────────────────┘

The Three Components

JVM (Java Virtual Machine)
  • Abstract computing machine that runs bytecode (.class files)
  • Platform-specific implementation (Windows JVM ≠ Linux JVM)
  • Responsible for Just-In-Time (JIT) compilation to native code
  • Provides memory management and garbage collection
  • Isolates Java code from hardware/OS details
JRE (Java Runtime Environment)
  • JVM + Java Standard Library (java.lang, java.util, java.io, etc.)
  • Needed to run Java programs
  • Does NOT include compiler (javac) or other dev tools
  • Lightweight; can be distributed to end users
JDK (Java Development Kit)
  • JRE + compiler + tools for development
  • Includes: javac, javadoc, jdb, jshell, and more
  • Needed to develop Java programs
  • Larger download; typically only needed on developer machines

What You Install

# Check JDK installation
java -version        # Shows JRE/JVM version
javac -version       # Shows compiler version (JDK only)
For this course: Install the JDK. The JDK includes everything (JVM + JRE + tools).

3. JIT Compilation

Compilation Pipeline

┌──────────────┐       ┌────────────┐       ┌─────────────────┐
│ .java source │─ ──→ │ .class     │─ ──→ │ JVM JIT         │
│    file      │ javac │ bytecode   │ java │ Compiler        │
│              │       │ (portable) │      │ ↓               │
└──────────────┘       └────────────┘      │ Native machine  │
                                           │ code (fast!)    │
                                           └─────────────────┘

Key Concepts

  • Intermediate compilation (javac): Source code → platform-independent bytecode
  • JIT (Just-In-Time): JVM compiles hot bytecode paths to native machine code during execution — makes Java fast
  • Trade-off: First run is slower (JIT warm-up), but subsequent runs are very fast

Example Execution Path

# Step 1: Compile
javac HelloWorld.java    # Creates HelloWorld.class (bytecode)

# Step 2: Run (JVM starts)
java HelloWorld          # JVM loads .class, JIT compiles frequently-run methods to native code
Why JIT is clever: The JVM profiles which methods run most often. Those hot paths are compiled to native machine code by JIT. Cold code stays as bytecode. This hybrid approach gives you portability + speed.

6. Hello World — First Program

Complete HelloWorld.java with Inline Explanations

// HelloWorld.java — File name MUST match the public class name

public class HelloWorld {      // public = accessible anywhere; class = template for objects
    public static void main(String[] args) {  // Entry point — JVM calls this first
        // public    = accessible by JVM launcher
        // static    = belongs to the class, no instance needed to call it
        // void      = method returns nothing
        // main      = special name — JVM looks for this signature
        // String[]  = array of text (command-line arguments)
        // args      = array name (could be any name, but main is the standard name)

        System.out.println("Hello, World!");
        // System    = built-in class from java.lang package
        // out       = static PrintStream field (object that writes to console)
        // println() = method that prints text and moves to new line
    }
}

Compile and Run

# Compile: converts .java source to .class bytecode
javac HelloWorld.java
# Output: HelloWorld.class created

# Run: JVM executes the bytecode
java HelloWorld
# Output: Hello, World!

Common Beginner Mistakes

// WRONG — file is named Main.java, class is named HelloWorld
// This will cause: error: class HelloWorld is public, should be declared in a file named HelloWorld.java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

// CORRECT — file name matches public class name
// File: HelloWorld.java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}
// WRONG — wrong main signature (compiler won't find entry point)
public class HelloWorld {
    public static void main() {  // Missing String[] args parameter
        System.out.println("Hello");
    }
}
// Running java HelloWorld fails: Error: Could not find or load main class

// CORRECT — exact signature required by JVM
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}

More Complex Example

public class Greeting {
    public static void main(String[] args) {
        String name = "Alice";
        int age = 25;
        double height = 5.7;

        System.out.println("Name: " + name);
        System.out.println("Age: " + age);
        System.out.println("Height: " + height);

        System.out.println("In 10 years, age will be: " + (age + 10));
    }
}

javac Greeting.java
java Greeting
# Output:
# Name: Alice
# Age: 25
# Height: 5.7
# In 10 years, age will be: 35

7. Compilation Model

Source-to-Execution Flow

┌──────────────────┐
│  HelloWorld.java │  (Human-readable source code)
│   (Source file)  │
└────────┬─────────┘
         │ javac compiler
         ↓
┌──────────────────┐
│ HelloWorld.class │  (Bytecode — platform-independent)
│   (.class file)  │
└────────┬─────────┘
         │ java command
         ↓
┌──────────────────┐
│      JVM         │  (Interprets bytecode + JIT compiles to native code)
│  (Runtime)       │
└────────┬─────────┘
         │
         ↓
┌──────────────────┐
│  Program Output  │  (Results on screen/file)

Step-by-Step Process

Step 1: Compile
  • javac reads HelloWorld.java
  • Checks syntax and types
  • Produces HelloWorld.class (bytecode)
  • Does NOT produce native executable
Step 2: Run
  • java command loads HelloWorld.class into memory
  • JVM verifies bytecode is safe
  • JIT compiler translates hot code paths to native machine code
  • Program executes on your CPU

Example: Compile Error

public class Bad {
    public static void main(String[] args) {
        int x = "hello";  // ERROR: cannot assign String to int
        System.out.println(x);
    }
}

javac Bad.java
# Error: incompatible types: String cannot be converted to int
# javac STOPS here, no .class file created

Example: Runtime Error

public class Runtime {
    public static void main(String[] args) {
        int[] arr = new int[5];
        System.out.println(arr[10]);  // Index 10 doesn't exist (array is size 5)
    }
}

javac Runtime.java  # Compiles fine
java Runtime        # Crashes at runtime
# Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 10 out of bounds for length 5
Compile-time vs Runtime: Java is statically typed, so many errors are caught by javac. But logic errors, division by zero, array bounds — these happen at runtime. Always test your code!

The .class File

# After javac, you get bytecode
javac HelloWorld.java

# Look at it (binary, not human readable)
ls -la HelloWorld.class
# -rw-r--r-- 1 user user 427 May 10 12:34 HelloWorld.class

# You can't read it directly, but tools can inspect it
javap -c HelloWorld  # Shows the bytecode instructions

8. Package System

Packages Organize Code

  • Package: Namespace for grouping related classes
  • Convention: Reverse domain name: com.company.project.feature
  • Purpose: Avoid name collisions, organize large projects, control access (package-private)

Package Declaration Syntax

package com.example.utils;  // Must be FIRST statement in file (before any imports)

public class StringHelper {
    public static String reverse(String s) {
        return new StringBuilder(s).reverse().toString();
    }
}

Directory Structure Must Match Package Name

src/
└── com/                           ← First level of package
    └── example/                    ← Second level
        └── utils/                  ← Third level
            └── StringHelper.java   ← package com.example.utils;

File Path vs Package Name

# File location: src/com/example/utils/StringHelper.java
# Package inside file: package com.example.utils;
# Class name: StringHelper
# Fully qualified name: com.example.utils.StringHelper

# To compile from project root:
javac src/com/example/utils/StringHelper.java

# To run (won't work without proper setup):
java com.example.utils.StringHelper

Real-World Example

// File: src/com/myapp/user/User.java
package com.myapp.user;

public class User {
    private String name;
    private int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }
}

// File: src/com/myapp/main/App.java
package com.myapp.main;

import com.myapp.user.User;  // Import from another package

public class App {
    public static void main(String[] args) {
        User u = new User("Bob", 30);
        System.out.println(u.getName());
    }
}

Compiling Multi-Package Project

# From project root, compile all source files
javac src/com/myapp/user/User.java src/com/myapp/main/App.java

# Or compile all Java files in src/
javac src/com/myapp/**/*.java

# To run (classpath must include src/)
java -cp src com.myapp.main.App
# Output: Bob

Default Package (No Package Declaration)

// NO package statement — belongs to default package
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Default package");
    }
}
Avoid default package: It works for tiny programs, but doesn't scale. Always use packages in real code. Default package can't be imported by other packages.

9. Import Statements

Three Types of Imports

Single-Type Import (Specific)
  • Import one specific class from a package
  • Recommended: Clear what you're using
  • Example: import java.util.ArrayList;
On-Demand Import (Wildcard)
  • Import all public classes from a package
  • Not recommended: Unclear dependencies, potential name collisions
  • Example: import java.util.*;
Static Import
  • Import static members (methods, constants) from a class
  • Use sparingly: Can reduce readability if overused
  • Example: import static java.lang.Math.PI;

Single-Type Import Example

import java.util.ArrayList;      // Specific class

public class ListDemo {
    public static void main(String[] args) {
        ArrayList<String> list = new ArrayList<>();  // Can use short name
        list.add("Apple");
        list.add("Banana");
        System.out.println(list);
    }
}

javac ListDemo.java
java ListDemo
# Output: [Apple, Banana]

On-Demand Import Example

import java.util.*;  // All classes from java.util

public class MapDemo {
    public static void main(String[] args) {
        HashMap<String, Integer> map = new HashMap<>();
        ArrayList<String> list = new ArrayList<>();
        // Can use HashMap, ArrayList, etc. without prefixing
    }
}
Wildcard imports hide dependencies: A reader can't easily see what classes you're using. Use single-type imports for clarity (IDEs can auto-add them).

Static Import Example

import static java.lang.Math.PI;      // Import constant
import static java.lang.Math.sqrt;    // Import method

public class MathDemo {
    public static void main(String[] args) {
        double radius = 5;
        double area = PI * radius * radius;
        System.out.println("Area: " + area);
        System.out.println("sqrt(16) = " + sqrt(16));
    }
}

javac MathDemo.java
java MathDemo
# Output:
# Area: 78.53981633974483
# sqrt(16) = 4.0

Auto-Imported Packages

  • java.lang: ALWAYS imported automatically (String, System, Math, Object, etc.)
  • You never write import java.lang.String; — it's always available
  • All other packages require explicit import
// String is from java.lang, no import needed
public class NoImport {
    public static void main(String[] args) {
        String s = "Hello";            // String is available
        System.out.println(s);         // System is available
        Math.sqrt(16);                 // Math is available
        // These are java.lang classes — no import required
    }
}

Import Statement Rules

  • All imports must come AFTER package declaration (if any)
  • All imports must come BEFORE class declaration
  • Import order: typically organize alphabetically (tools do this automatically)
  • Duplicate imports are ignored
  • Name collision: If two packages have same class name, use fully qualified name
package com.example;

import java.util.List;         // Single-type imports first
import java.util.ArrayList;
import java.io.*;              // On-demand if necessary
import static java.lang.Math.*;

public class ImportOrder {
    // Class definition
}

Name Collision Example

// Both java.util and java.sql have Date class
import java.util.Date;         // Imports java.util.Date

public class DateDemo {
    public static void main(String[] args) {
        Date d1 = new Date();              // Uses java.util.Date
        java.sql.Date d2 = new java.sql.Date(0);  // Fully qualified for java.sql.Date
    }
}

 * for readability.
 *
 * Can have blank lines inside.
 */

Javadoc Comments

/**
 * Calculates the sum of two integers.
 *
 * Javadoc uses /** to start and has special tags.
 * This generates HTML documentation from your code.
 *
 * @param a the first number
 * @param b the second number
 * @return the sum of a and b
 * @since 1.0
 * @author John Doe

Common Javadoc Tags

  • @param — describes a method parameter
  • @return — describes the return value
  • @throws — describes exceptions the method can throw
  • @author — author name
  • @since — version when added
  • @deprecated — marks class/method as outdated

Complete Javadoc Example

/**
 * Calculator utility for basic arithmetic.
 *
 * <p>Provides static methods for common operations.
 * All methods accept integer inputs.</p>
 *
 * @author Alice Smith
 * @since 1.0
 * @version 1.2
 */
public class Calculator {

    /**
     * Multiplies two integers.
     *
     * @param x the first number
     * @param y the second number
     * @return the product x * y
     * @throws IllegalArgumentException if either number is negative
     * @since 1.0
     */
    public static int multiply(int x, int y) {
        if (x < 0 || y < 0) {
            throw new IllegalArgumentException("Numbers must be non-negative");
        }
        return x * y;
    }

    /**
     * Checks if a number is prime.
     *
     * @param n the number to check
     * @return true if n is prime, false otherwise
     * @since 1.1
     */
    public static boolean isPrime(int n) {
        if (n < 2) return false;
        for (int i = 2; i * i <= n; i++) {
            if (n % i == 0) return false;
        }
        return true;
    }
}

Generate Javadoc HTML

# javadoc reads all .java files and generates HTML documentation
javadoc Calculator.java

# Output: creates doc/ directory with HTML files
# Open doc/index.html in browser to see generated docs

Comment Best Practices

  • Comments explain WHY, not WHAT: Code shows what it does, comments explain reasoning
  • Avoid obvious comments: Don't write x++; // increment x
  • Use Javadoc for public APIs: Every public class and method needs Javadoc
  • Keep comments updated: Outdated comments are worse than no comments
Good comment examples:
  • // HACK: Workaround for bug in legacy system
  • // Performance optimization: cache result to avoid O(n²) lookup
  • // Expected format: YYYY-MM-DD (ISO 8601)

12. Single-File Programs Java 11+

No Compilation Needed

  • java command: Can run .java files directly (no javac needed)
  • Automatic compilation: JVM compiles on the fly
  • Use case: Scripts, one-off programs, small utilities
  • Limitation: Only works if file contains a single top-level public class

Traditional Way (Still Works)

# Step 1: Compile
javac HelloWorld.java

# Step 2: Run
java HelloWorld

New Way (Java 11+)

# Single command — no separate compile step
java HelloWorld.java

Example: Single-File Script

// File: Temperature.java
// Run: java Temperature.java 100 F
// No separate javac step needed

public class Temperature {
    public static void main(String[] args) {
        if (args.length < 2) {
            System.out.println("Usage: java Temperature.java <value> <C|F>");
            return;
        }

        double temp = Double.parseDouble(args[0]);
        String unit = args[1].toUpperCase();

        if (unit.equals("C")) {
            double fahrenheit = (temp * 9/5) + 32;
            System.out.println(temp + "°C = " + fahrenheit + "°F");
        } else if (unit.equals("F")) {
            double celsius = (temp - 32) * 5/9;
            System.out.println(temp + "°F = " + celsius + "°C");
        } else {
            System.out.println("Unknown unit: " + unit);
        }
    }
}

java Temperature.java 32 C
# Output: 32.0°C = 89.6°F

java Temperature.java 98.6 F
# Output: 98.6°F = 37.0°C
When to use single-file mode: Scripts, quick tests, learning. For real projects, use packages and multiple files (traditional compilation model).

13. Command-Line Arguments

Accessing Arguments via main(String[] args)

public class Arguments {
    public static void main(String[] args) {
        // args is an array of Strings from command line

        System.out.println("Total arguments: " + args.length);

        // Print all arguments
        for (int i = 0; i < args.length; i++) {

}

Running with Arguments

javac Arguments.java

# Output:

Using Enhanced for Loop

public class PrintArgs {
    public static void main(String[] args) {
        if (args.length == 0) {
            System.out.println("No arguments provided");
            return;
        }

        System.out.println("Arguments:");
        for (String arg : args) {
            System.out.println("  - " + arg);
        }
    }
}

java PrintArgs apple banana cherry
# Output:
# Arguments:
#   - apple
#   - banana
#   - cherry

Real-World Example: Sum Calculator

public class Sum {
    public static void main(String[] args) {
        if (args.length == 0) {
            System.out.println("Usage: java Sum <number1> <number2> ...");
            return;
        }

        int total = 0;

        for (String arg : args) {
            try {
                int num = Integer.parseInt(arg);  // Convert String to int
                total += num;
            } catch (NumberFormatException e) {
                System.out.println("Error: '" + arg + "' is not a valid integer");
            }
        }

        System.out.println("Sum: " + total);
    }
}

java Sum 10 20 30
# Output: Sum: 60

java Sum 5 abc 10
# Output:
# Error: 'abc' is not a valid integer
# Sum: 15

Command-Line with Spaces and Quotes

# Single argument with spaces must be quoted
java PrintArgs "hello world" test
# Output:
# Arguments:
#   - hello world
#   - test

# Without quotes, it's two arguments
java PrintArgs hello world test
# Output:
# Arguments:
#   - hello
#   - world
#   - test

Example: Greeting Program

public class Greeting {
    public static void main(String[] args) {
        String name = (args.length > 0) ? args[0] : "World";
        String greeting = (args.length > 1) ? args[1] : "Hello";

        System.out.println(greeting + ", " + name + "!");
    }
}

java Greeting
# Output: Hello, World!

java Greeting Alice
# Output: Hello, Alice!

java Greeting Bob "Hi there"
# Output: Hi there, Bob!
Best practice: Always check args.length before accessing array elements to avoid ArrayIndexOutOfBoundsException.

Converting Arguments to Other Types

public class TypeConversion {
    public static void main(String[] args) {
        if (args.length < 2) {
            System.out.println("Usage: java TypeConversion <int> <double>");
            return;
        }

        // String to int
        int count = Integer.parseInt(args[0]);

        // String to double
        double price = Double.parseDouble(args[1]);

        // String to boolean
        boolean flag = Boolean.parseBoolean(args.length > 2 ? args[2] : "false");

        System.out.println("Count: " + count + " (int)");
        System.out.println("Price: " + price + " (double)");
        System.out.println("Flag: " + flag + " (boolean)");
        System.out.println("Total: " + (count * price));
    }
}

java TypeConversion 5 9.99 true
# Output:
# Count: 5 (int)
# Price: 9.99 (double)
# Flag: true (boolean)
# Total: 49.95

Summary

Key Takeaways

  • JVM makes Java portable: Compile once (.class), run anywhere
  • JIT compilation: Bytecode → native code during execution = speed + portability
  • JDK is what you install: It includes JRE, JVM, and compiler
  • Packages organize code: Use reverse domain naming (com.example.feature)
  • main(String[] args): Exact signature required as entry point
  • Comments matter: Javadoc generates documentation automatically
  • JShell for learning: Test code instantly without boilerplate
  • Single-file programs (Java 11+): java file.java — no javac needed

Common Errors Checklist

  • class X is public, should be declared in a file named X.java → File name must match public class name
  • Could not find or load main class → main signature is wrong, or file/package path is incorrect
  • cannot find symbol → Missing import or typo in class/method name
  • incompatible types → Type mismatch (String assigned to int, etc.)
  • No class definition found → Forgot to compile, or .class file not in classpath
